# DockyardOS workflow

- Read `dockyard_context` with the current project root before substantial work.
- Use `dockyard_recommend` to choose relevant skills, agents, tools, MCPs, providers, and security gates instead of loading everything.
- Use `dockyard_team_start`, `dockyard_team_status`, and `dockyard_team_advance` for multi-phase work.
- Keep implementation writers isolated; keep security/QA/release reviewers independent.
- Use `dockyard_policy` before risky commands and preserve Claude Code's native permission system.
- Save `dockyard_checkpoint` at milestones and before risky transitions.
- High-security projects keep OWASP, Gitleaks, OSV-Scanner, Semgrep, threat modeling, independent review, and authorized Strix verification when selected.
